## Outcome

DaVinci ResolveのColor Pageで、<b>高彩度だけを数値的に圧縮するDCTL</b>を完成させる。標準構成は <code>Source → CST In → SatComp → CST Out</code>。SatCompはDWG/DaVinci Intermediateだけを外部processing contractとし、一定以下の彩度は完全保持、高彩度では <code>S_out = f(S_in)</code> に従って滑らかに圧縮する。色相とOklab lightnessは意図的に変更しない。

## Problem / Desired Flow

通常のSaturationノブでは、高彩度だけを選択的かつ再現可能な数値関係で抑えることが難しい。SatCompではユーザーがCSTで入力をDWG/DIへ揃え、SatCompの少数controlだけを調整し、後段CSTで目的のoutputへ戻す。素材のcamera gamut / log / output standardへの対応はCSTへ委譲し、SatComp自身は一つの明確なcolor contractだけを処理する。

## Product Contract

- low / mid saturationはidentity。
- compression regionでも <code>S_out <= S_in</code>。saturation boostはしない。
- <code>f(S)</code> はmonotonic。soft transitionに不連続を作らない。
- Oklab <code>L</code> とhueを保持し、chromaだけを縮小する。
- hidden ceiling、hidden gamut clip、hidden luminance weightingを入れない。
- DWG/DI以外をSatCompへ直接入力することはunsupported。
- output gamut/tone mappingはSatCompの責務外。

## Saturation Metric

Public unit:

<code>S = 100 * C / L</code>

ここでOklab/OkLChの <code>C = sqrt(a²+b²)</code>。100倍はUI可読性のためのSatComp固有scaleであり、百分率でも上限でもない。100超を許容する。

Processing path:

<code>DWG/DI → DI inverse OETF → linear DWG → CIE XYZ D65 → Oklab → S</code>

DWG↔XYZとDI encode/decodeはBlackmagic公式v1.1、XYZ D65↔Oklabはcurrent W3C CSS Color 4をreference mathとする。Oklab forward nonlinear stepはLMS各成分へ<b>符号付きreal cube root</b>を適用し、negative値へ一般的な <code>pow(x, 1/3)</code> を直接使わない。DWGはD65なのでwhite-point adaptationを追加しない。正の一様scene exposure scaleではOklabのL/Cが同じcube-root factorでscaleするため、<code>C/L</code> は不変となる。数値guardとして <code>L <= 1e-6</code>、<code>C <= 1e-7</code>、<code>S_in <= 1e-7</code>、または非有限intermediateではcompressionを適用せず原RGBを返す。これはdivision/neutral保護であり、near-blackを芸術的に弱めるhidden luminance weightingではない。

Compression後:

<code>C_out = C_in * (S_out / S_in)</code>

としてa/bを一様scaleし、Lとhを保持してOklab→XYZ→linear DWG→DIへ戻す。

## Scalar Transfer / UI

Primary UIは4つだけ。

- <b>Threshold S</b>: soft-knee中心。<code>0..200</code>を最低限操作可能、default <code>25.0</code>, step <code>0.1</code>。R5/R7で有効S分布を確認し、必要なら上限だけ200以上へ拡張してよい。
- <b>Compression %</b>: <code>0..100</code>, default <code>0.0</code>, step <code>0.1</code>。0%=1:1、50%=2:1相当、75%=4:1相当、90%=10:1相当、100%=limiter相当。
- <b>Softness %</b>: <code>0..100</code>, default <code>20.0</code>, step <code>0.1</code>。Thresholdに対する相対knee幅。Threshold=25 / Softness=20%ならfull knee widthは10 S。
- <b>Bypass</b>: exact before/after用checkbox。

<code>A = Compression/100</code>, <code>m = 1-A</code>, <code>T = Threshold</code>, <code>P = Softness/100</code>, <code>K = 2*T*P</code>。したがって <code>lo=T*(1-P)</code>, <code>hi=T*(1+P)</code> で、hidden clampなしに <code>lo>=0</code> を保証する。

Hard knee <code>K=0</code>:

- <code>S <= T: f(S)=S</code>
- <code>S > T: f(S)=T + m(S-T)</code>

Soft knee <code>K>0</code>:

- <code>S <= lo: f(S)=S</code>
- <code>lo < S < hi: f(S)=S - A*(S-lo)^2/(2*K)</code>
- <code>S >= hi: f(S)=T + m(S-T)</code>

この式は <code>0<=A<=1</code> で <code>0<=f(S)<=S</code>、value/first derivative連続、monotonic、no-boost。Compression=0は全域identity、Compression=100%ではknee上端以降が <code>S_out=T</code>。

v1ではRatio / Ceiling / input-output curve point editor / color-space selectorをprimary UIへ置かない。

## Color Management Contract

Canonical middle spaceは <b>DaVinci Wide Gamut + DaVinci Intermediate</b> 固定。共通条件は「SatComp直前のactual RGBがDWG/DI」であること。

Supported topology A — explicit CST sandwich:

<code>Source/native working space → CST In (source → DWG/DaVinci Intermediate) → SatComp → CST Out (DWG/DaVinci Intermediate → destination)</code>

Input CSTは Output Color Space=DaVinci Wide Gamut / Output Gamma=DaVinci Intermediate とし、SatComp前のtone mapping / gamut mappingは使用しない。

Supported topology B — already managed DWG/DI:

RCM / timeline / group等でSatComp node入力が既にDWG/DIなら、前後へ重複CSTを追加せずproject/output color managementへ委譲する。source spaceを再度CST Inへ指定して二重変換する構成はunsupported例としてREADMEへ記載する。

SatCompは入力spaceを自動判定せず、内部color-space selectorも持たない。Output側でdeliveryに必要なrendering / gamut mappingを行えるが、その結果は <code>f(S)</code> の数値contract外。

## Protected Behavior

- Thresholdのuntouched regionは原DWG/DI RGBをexact fast-pathで返す。
- Compression=0 / Bypassも原RGBを返す。
- finite negative RGB / RGB > 1を0..1へclampしない。
- alphaを意図的に変更しない。
- finite inputからSatComp自身が新しいNaN/Infを作らない。
- old PR #1の仕様は、このBriefで再採用された部分以外はauthorityを持たない。

- <b>Security / privacy:</b> N/A — DCTLはpixel-local演算で、network・credential・外部送信・永続データを持たない。
- <b>Data preservation / recovery:</b> source media / timeline stateを変更しない。DCTL導入はファイル配置のみで、削除により除去可能。host検証で作る一時stateはowned/scratchを使う。
- <b>Compatibility:</b> target Resolve 21.xのDCTL compile/runtimeをR6で実証し、buildをevidenceへ固定する。
- <b>Performance / usability:</b> SAT-019 + R6/R7で確認する。
- <b>Distribution / migration:</b> public installer/marketplace migrationはv1 Case外。旧Draft PR #1は未merge referenceでありmigration sourceではない。
