# Product Requirements

## 1. 製品概要

Press Machine は DaVinci Resolve 用の DCTL 彩度コンプレッサーです。

高彩度領域だけを soft-knee で自然に圧縮し、低彩度領域、入力の輝度成分、色差ベクトルの方向を可能な限り維持します。音声コンプレッサーに似た Threshold、Ratio、Knee の考え方を、RGB から分離した色差量に適用します。

中核となる製品定義:

> 見た目の彩度が高すぎる部分を見つけ、信号として正確かつ予測可能に圧縮する。

そのため、圧縮対象を判断する Detector と、実際に RGB を縮小する処理を分離して設計します。

## 2. 目的

- 一定以上に強い色だけを抑える。
- 彩度の急なクリップ感を避ける。
- 低彩度の肌、ニュートラル、微妙な色差を不用意に変えない。
- 圧縮による意図しない輝度変化と色相回転を抑える。
- 極端な入力や UI 設定でも安定して動作する。
- カーブ表示により、現在の圧縮特性を確認できるようにする。
- 人間の感覚に大きく反しない方法で高彩度領域を検出する。
- 検出後の圧縮量は、数式とグラフから予測できるようにする。

## 3. コア処理

入力 RGB を `rgb`、輝度ウェイトを `w` とします。

```text
Y       = dot(rgb, w)
chroma  = rgb - Y
sat_in  = length(chroma)
sat_cmp = compress(sat_in)
chroma_out = chroma * safe_scale(sat_cmp, sat_in)
wet_rgb = Y + chroma_out
out_rgb = mix(rgb, wet_rgb, Mix)
```

`compress()` は Threshold、Ratio、Knee、Amount による単調増加の soft-knee compression とします。

ただし、Threshold と比較するための検出値は知覚寄りの相対彩度とし、実際の RGB 再構成では元の色差ベクトルを機械的に縮小します。

## 4. 必須 UI

- `Amount`
- `Threshold`
- `Ratio`
- `Knee`
- `Input Color Space`
- `Black Protect`

グラフを採用する場合は、診断用パラメータとして `Show Graph` の追加を検討します。

## 5. 機能要件

### PR-01: 完全バイパス

- `Amount = 0` の出力は入力と一致する。
- `Ratio = 1` の出力は入力と一致する。

浮動小数点誤差を避けるため、可能なら条件分岐で入力を直接返します。

### PR-01A: Amount の線形性

Amount は完全圧縮によって減少する彩度量を線形に制御します。

- 25%: 完全圧縮時の減少量の 25%
- 50%: 完全圧縮時の減少量の 50%
- 75%: 完全圧縮時の減少量の 75%

内部マッピングによる感度カーブを設けません。

UI 表示は `0-100`、内部値は `0.0-1.0` とし、100で除算するだけの線形変換を使用します。

### PR-02: 低彩度域の保護

hard-knee の場合、`sat_in <= Threshold` は変更しません。

soft-knee の場合は Knee 下端より下を変更せず、Knee 内だけで連続的に圧縮へ移行します。

### PR-03: 輝度保持

wet 処理では入力から求めた `Y` を変更せずに RGB を再構成します。

ただし、RGB ガマット境界、負値処理、非線形符号化空間での演算によって知覚上の明るさが完全に一定になるとは限りません。

### PR-04: 色相方向の保持

色差ベクトルにはスカラーのみを乗算し、方向を変更しません。

### PR-05: 連続性

- 圧縮カーブは単調増加であること。
- Knee 境界で出力値が連続であること。
- 原則として Knee 境界で一次微分も連続であること。

Threshold は Knee の中心を表し、Knee は遷移帯の全幅を表します。

```text
Knee start = Threshold - Knee / 2
Knee end   = Threshold + Knee / 2
```

### PR-05A: Ratio と Limiter

Ratio は一般的なコンプレッサー比として定義します。

```text
output excess = input excess / Ratio
```

`Infinity:1` では出力彩度を Threshold に制限します。Knee がある場合は soft limiter、Knee が 0 の場合は hard saturation limiter として動作します。

RGB チャンネル単位のクリッピングや、出力 RGB の 0-1 クランプは行いません。

### PR-06: 数値安全性

- `sat_in` が 0 または極小の場合に除算しない。
- Knee が 0 の場合は hard-knee として扱う。
- NaN または Inf を生成し得る式を避ける。
- 極端な RGB 値でも不要なハードクランプを行わない。

### PR-07: グラフ整合性

グラフを実装する場合、ピクセル処理と同じ圧縮関数を呼び出します。カーブ計算を別実装として複製しません。

### PR-08: 明るさから独立した彩度判断

明るさだけが異なり、色の濃さが同じと判断できる色は、可能な限り同程度に圧縮します。

通常領域では、Resolve ベクトルスコープ中心からの距離に対応する色差半径を使用します。明るさは彩度量の増減には使わず、黒付近の検出抑制だけに使用します。

### PR-09: 黒付近の安定性

ほぼ黒い領域では、微小な RGB 差を高彩度として過大評価しません。黒付近の反応抑制は内部安全処理とし、初期版では専用 UI を設けません。

`Black Protect` が ON の場合のみ保護を適用します。OFF では黒付近も通常の彩度コンプレッション対象とします。初期版の保護範囲は固定です。

保護範囲は最小限とし、暗い有彩色や夜景の色を保護対象に含めません。

### PR-10: 複数色空間対応

入力色空間を UI で選択し、内部の共通処理空間へ変換してから同一の彩度圧縮処理を適用します。

初期対応:

- DaVinci Wide Gamut / Intermediate
- Rec.709 Gamma 2.4
- Rec.709 Scene
- ACEScct / AP1
- ARRI LogC3 / ARRI Wide Gamut 3
- ARRI LogC4 / ARRI Wide Gamut 4
- ACEScg / AP1 Linear

変換では transfer function と RGB primaries の両方を扱います。

ARRI 入力は `LogC3/AWG3` および `LogC4/AWG4` の完全な組み合わせとして扱います。

LogC3 は EI 800 固定で実装し、EI 選択 UI は設けません。ARRIRAW のデコードや EI メタデータ処理は対象外です。

曖昧な名称の `Linear` は使用せず、ACEScg / AP1 Linear と明記します。

Rec.709 Gamma 2.4 と Rec.709 Scene は別の入力モードとして扱います。

### PR-11: Detector と圧縮処理の分離

- Detector は、見た目の鮮やかさに近い基準で圧縮対象と圧縮量を決める。
- 圧縮処理は、元の輝度と色差方向を維持しながら色差量を縮小する。
- Density、明るさの意図的な変化、フィルムルックは加えない。

### PR-12: 色相に対して中立

- 色相別の重み付け、優先保護、圧縮強度補正を行わない。
- 同じ検出彩度には同じ gain reduction を適用する。
- 色差ベクトルの方向を変えず、中心方向へ縮小する。
- ベクトルスコープ上で同じ半径の色は、同じ設定で等しい割合の半径変化を目標とする。

検証には DaVinci Resolve の通常のベクトルスコープを使用します。比較時はスコープ設定とカラーマネジメント条件を固定します。

### PR-13: Scope-based Detector

- Detector は二つの直交する色差信号から半径を求める。
- 色相角は圧縮判断へ使用しない。
- 同じ半径には同じ圧縮係数を返す。
- 輝度信号は black protection にのみ使用する。

### PR-14: Threshold の表示範囲

Threshold UI は `0-100` とし、Resolve ベクトルスコープの基準半径に線形対応させます。

入力彩度は100でクランプせず、100を超える信号も通常の圧縮式で処理します。

## 6. 非目標

初期版には次を含めません。

- Density または subtractive color のエミュレーション
- Luma contrast
- Makeup saturation
- 自動ガマットマッピング
- 色相別の圧縮
- spatial processing
- temporal processing
- ノイズ除去
- ローカルコントラスト

## 7. 受け入れ条件

- グレースケール入力が全設定で変化しない。
- `Amount = 0`、`Ratio = 1` がバイパスになる。
- Knee 下端より低い彩度が変化しない。
- 高彩度ほど圧縮量が増える。
- 圧縮後彩度は入力彩度を超えない。
- 入力彩度が増えたとき、出力彩度が逆行しない。
- 同一色度の露出違いで圧縮量が大きく変化しない。
- 色相だけが異なる同彩度パッチで、圧縮率が一致する。
- ベクトルスコープ上で意図しない色相回転が発生しない。
- 黒付近の微小な色差に過敏に反応しない。
- 代表的な RGB サンプルと極端値で NaN/Inf が発生しない。
- グラフと実際の圧縮関数が一致する。

## 8. 品質評価用サンプル

- グレースケールランプ
- 一定 Y 上の彩度ランプ
- RGB および CMY の高彩度パッチ
- 肌色付近の低彩度から中彩度ランプ
- 負 RGB を含む広色域サンプル
- 1.0 を超える scene-linear RGB
- 非常に小さい chroma を持つサンプル
